# AI 学习监督器 · 产品设计 v0.1

> 定位：不是一个打卡工具，而是一个「AI 出题验收」的学习进度系统。
> 你学完一个学习单元 → 随时发起检测 → AI 按评分标准打分 → **通过后进度条才增长**（v1.3 起不要求按顺序，可以跳着做）。

---

## 1. 核心决策：Day 是学习单元，不是自然日

这是整个产品的地基，也是区别于所有打卡类 App 的地方。

| 对比 | 传统打卡 App | 本产品 |
|---|---|---|
| 时间单位 | 自然日（今天没学 = 欠债） | **Day = 约 60 分钟学习量** |
| 推进方式 | 按日历推进 | 按完成量推进，哪天有空就多学几个 |
| 落后感 | 强（断签、红字） | 无。只有「还剩 N 个 Day」 |
| 中断恢复 | 补签很尴尬 | 随时回来接着做 Day 7 |

**规则：**

- 1 Day ≈ **60 分钟**（默认，可在目标里改成 30 / 45 / 90）
- 一个 Day 可以当天做完，也可以拆三天做，**不影响 Day 的编号**
- 一天做 3 个 Day 完全合法；也可以先跳到后面的 Day 做（v1.3 起没有顺序限制）
- 自然日期只用于两件事：**统计学习时长** 和 **遗忘复检的触发窗口**，不参与计划推进

> 好处：进度条永远是单调可解释的（已完成 Day ÷ 总 Day），不会因为"今天没学"而倒退。
> 唯一允许倒退的情况是**复检答错**（见第 6 节）。

## 2. 概念模型

```
Goal（目标）
 └─ Plan（计划，可多版本）
     └─ Day（Day 1 … Day N，每个约 60 分钟）
         ├─ Task（1~3 个任务勾选项，带验收标准）
         └─ Exam（完成所有 Task 后解锁，5~10 分钟 3 道题）
             ├─ Question × 3
             └─ Score（Rubric 四维评分）
                 └─ ProgressEvent（进度增减事件，可正可负）
```

| 概念 | 含义 | 关键字段 |
|---|---|---|
| **Goal** | 一个学习目标，例如「30 天入门 React」 | 目标文档、截止日期（可选）、每日时长、当前水平 |
| **Plan** | AI 生成后经你确认的计划，带版本号 | 总 Day 数、阶段划分、生成模型、是否生效 |
| **Day** | 学习单元，进度条的计量单位 | 序号、标题、预计分钟、任务清单、状态 |
| **Task** | Day 内的勾选项 | 标题、预计分钟、验收标准、关联材料、是否完成 |
| **Exam** | 针对某个 Day 的考试 | 题目、作答、评分、耗时、token 成本 |
| **ProgressEvent** | 进度事件流水 | 增减量、原因、关联 Day、时间 |

**为什么进度要用事件流水（Event Sourcing）而不是一个数字？**
因为要支持：回退、申诉、审计（"这 3% 是怎么来的"）、重算（改了权重之后）。直接存百分比，改一次规则就全废。

## 3. 主流程（7 步）

```
① 新建目标 ── 写目标文档（学什么 / 为什么 / 每天多久 / 什么水平）
       ↓
② AI 生成计划 ── 输出结构化 JSON ──→ ③ 评审页确认（可改、可删、可调时长）
       ↓
④ 学 Day N ── 勾选任务 + 计时 + 看材料
       ↓
⑤ 全部任务完成 ──→ 【开始考试】按钮亮起（不绑定自然日，随时可考）
       ↓
⑥ 考试（5~10 分钟，3 题）──→ AI 评分
       ↓
⑦ 通过 ── 进度条增长 ──→ 继续任意一天（不强制顺序）
   未通过 ── 生成补学任务 ──→ 重学后重考（可无限次）
```

**关键交互原则：**

- 检测是**你主动发起**的，不是定时弹窗；想什么时候考哪一天都行（v1.3 起取消顺序限制）。
- 考试不限制自然日：一天连考 3 次没问题。
- 考试过程中**不显示任何提示**，交卷后一次性给反馈（保证测的是真实水平）。

## 4. 计划是怎么生成出来的

### 输入（目标文档）

用户在新建目标时填一张表，内容作为 AI 的上下文：

- 学习目标（一句话 + 详细描述，Markdown）
- 截止日期（可选；不填则按 Day 数排）
- 每天可投入时长（默认 60 分钟 → 决定一个 Day 的大小）
- 当前水平（零基础 / 有基础 / 复习巩固）
- 可用材料（教材名、链接、已上传文档）
- 最终验收方式（做题？写代码？能做项目？讲给别人听？）

### 输出（结构化 JSON）

```json
{
  "goalId": "g_001",
  "title": "30 天入门 React，能独立写一个 Todo 应用",
  "totalDays": 30,
  "minutesPerDay": 60,
  "stages": [
    { "id": "s1", "title": "JSX 与渲染基础", "dayRange": [1, 5], "weight": 0.15 }
  ],
  "days": [
    {
      "idx": 1,
      "title": "认识 JSX：从 HTML 到 React 元素",
      "focus": "理解 JSX 本质是函数调用，不是模板语法",
      "estMinutes": 60,
      "materialRefs": ["doc://react-doc-jsx"],
      "tasks": [
        {
          "title": "阅读官方文档 JSX 章节",
          "estMinutes": 25,
          "acceptance": ["能用自己的话说出 JSX 被编译成什么"]
        },
        {
          "title": "手写 5 个小组件",
          "estMinutes": 35,
          "acceptance": ["5 个组件都能正确渲染", "能解释 key 的作用"]
        }
      ],
      "examFocus": ["JSX 编译结果", "key 的必要性", "表达式与语句的区别"]
    }
  ]
}
```

### 评审页（必须有，不能省）

AI 生成的计划**通常过于理想化**（第一天排 3 小时）。所以：

- 每个 Day 可展开看任务，能改标题、删任务、调预计时长
- 能整体重排（总 Day 数太多时可压缩）
- 显示统计：总 Day 数 × 每分钟 = 总投入时长，让你确认"我真的愿意投这么多小时吗"
- **确认后才写库**，未确认前只是草稿

### 重新规划

当连续 3 个 Day 的实际耗时 > 预估 × 1.5，或你主动点「计划不合理」时，触发重排：
保留已完成 Day 的成绩，从当前 Day 起重生成剩余部分，旧版本归档（`plan.version +1`）。

## 5. 考试设计（5~10 分钟）

| 项 | 设计 |
|---|---|
| 题量 | **3 题** |
| 题型 | 2 题客观（选择/填空）+ 1 题简答（要求你用自己的话解释） |
| 时间预算 | 客观题各 1.5 分钟，简答 3~5 分钟 → 合计 5~8 分钟 |
| 总分 | 100 分 |
| 评分维度 | 准确性 40 / 完整性 30 / 迁移应用 20 / 表达清晰 10 |
| 通过线 | **≥ 80 分** |
| 60~79 分 | 部分通过：进度条记 60%，可无限次重考提升 |
| < 60 分 | 不通过：进度条不动，AI 生成补学任务 |
| 补考 | 每次重新出题（不死记答案），仅保留最高分 |
| 防作弊 | 不显示答案直到交卷；记录作答耗时；检测异常粘贴；可选「答题时锁定窗口」 |

**为什么简答题必须有？**
选择题可以被"感觉"蒙对，简答题不能。2 选 1 简答能测出"知道了"和"学会了"的差距——这是整个产品可信度的来源。

**题目从哪来？**
不凭空出题。把该 Day 的任务标题、验收标准、关联材料一起喂给 AI，让它围绕**今天实际学的内容**出题。

## 6. 进度算法

### 单个 Day 的得分

```
day_score = Σ(维度得分 / 维度满分 × 维度权重)      ∈ [0, 1]

通过判定：
  day_score ≥ 0.80  → day.progress = 1.00，状态 passed
  0.60 ≤ s < 0.80   → day.progress = 0.60，状态 passed_partial（可重考提分）
  s < 0.60          → day.progress = 0.00，状态 failed（需重学）
```

### 总进度条

```
总进度 = Σ(day.progress × day.estMinutes) / Σ(day.estMinutes)
```

用预计时长加权，而不是简单平均 —— 否则一个 20 分钟的 Day 和一个 90 分钟的 Day 权重相同，进度会失真。

### 显示方式（重要）

不要只显示一根条，显示**双信息**：

```
███████████████░░░░░░░░░░░░░░  52%  掌握度
Day 16 / 30 · 已通过 15 个 · 1 个部分通过     ← 数量口径
```

### 回退规则（你已确认接受）

- 复检（Review）中某个已通过 Day 的抽测答错 → 该 Day 的 `progress` 下调，并写入负的 `ProgressEvent`
- 下调幅度：`-0.2`（下限 0），并在进度条上闪一下红色，不弹窗羞辱用户
- 允许在设置里关闭回退（默认开启）

### 复检触发

- 每完成 **4 个 Day**，或距上次复检满 **7 个自然日**（取先到者）
- 从已通过的 Day 里随机抽 2 个，每个出 1 道题，约 3 分钟
- 可以跳过，但会记录「已跳过」并在周报里提示

## 7. 界面清单（7 屏）

| # | 页面 | 核心内容 |
|---|---|---|
| 1 | **总览** | 大进度条 + 当前 Day 卡片 + 「继续学习」主按钮 + 今日已学时长 |
| 2 | **目标与文档** | 目标表单 + Markdown 编辑器 + 材料上传/粘贴 |
| 3 | **计划评审** | Day 列表（可展开编辑）+ 总投入统计 + 「确认生效」 |
| 4 | **Day 学习页** | 任务勾选清单 + 累计计时器 + 材料阅读区 + 底部「开始考试」 |
| 5 | **考试页** | 3 道题逐题作答 + 进度指示 + 交卷 |
| 6 | **成绩反馈页** | 分数 + 四维雷达图 + AI 逐题点评（引用你的原话）+ 下一步建议 |
| 7 | **统计页** | 学习热力图 + 累计时长 + 通过率 + 复检记录 + 成本统计（token/¥） |

**总览页的第一眼必须能回答三个问题：**
1. 我整体到哪了？（进度条）
2. 我下一步干什么？（当前 Day）
3. 我今天学了没有？（今日时长）

## 8. MVP 范围

### 必做（v0.1）

1. 新建目标 + 目标文档编辑
2. DeepSeek 生成计划 → JSON → 评审页确认
3. Day 列表 + Day 学习页（任务勾选）
4. 考试（3 题：2 客观 + 1 简答）
5. DeepSeek 评分 → 进度条增长 → 继续下一个想学的 Day
6. 本地 SQLite 持久化 + 手动导出 JSON 备份

### 第二版（v0.2）

- 复检机制 + 进度回退
- 统计页 / 热力图
- 计划重排
- 错题本（失败题自动收集，考前复习）

### 第三版（v0.3）

- 问答模式（AI 当助教提问，你一两句话回答；答完再追问一次）
- 多目标并行
- 桌面悬浮小窗 / 托盘常驻 / 系统通知
- 导出周报 Markdown

### 明确不做

- ❌ 不做完整笔记软件（Markdown 编辑够用）
- ❌ 不做多人 / 社交 / 排行榜
- ❌ v0.1 不做云同步（本地优先）
- ❌ 不做题库系统（题目由 AI 现场生成，不做刷题）
- ❌ 不做账号体系

## 9. 成功标准（自测）

用两周后问自己四个问题：

1. 我有没有因为"要考试"而真的学得更认真了？
2. 进度条数字和我真实掌握程度是否一致？
3. 每天打开它的成本有多高？（超过 3 分钟准备就太麻烦）
4. 一个月花了多少钱？（目标 < 30 元）

如果第 1 题答案是"没有"，说明这个产品的核心假设不成立，要立刻调整（大概率是考试太水或太烦）。
