## 2. 数据模型（SQLite DDL）

```sql
-- 目标
CREATE TABLE goal (
  id            TEXT PRIMARY KEY,
  title         TEXT NOT NULL,
  doc_md        TEXT NOT NULL DEFAULT '',   -- 目标文档（Markdown）
  deadline      TEXT,                        -- 可空；ISO 日期
  minutes_per_day INTEGER NOT NULL DEFAULT 60,
  level         TEXT,                        -- 'beginner' | 'basic' | 'review'
  status        TEXT NOT NULL DEFAULT 'active', -- active | archived
  created_at    TEXT NOT NULL
);

-- 计划（版本化）
CREATE TABLE plan (
  id            TEXT PRIMARY KEY,
  goal_id       TEXT NOT NULL REFERENCES goal(id),
  version       INTEGER NOT NULL,
  model         TEXT NOT NULL,
  raw_json      TEXT NOT NULL,               -- AI 原始输出，留档便于排查
  total_days    INTEGER NOT NULL,
  status        TEXT NOT NULL DEFAULT 'draft', -- draft | active | archived
  created_at    TEXT NOT NULL
);

-- 学习单元（核心表）
CREATE TABLE day (
  id            TEXT PRIMARY KEY,
  plan_id       TEXT NOT NULL REFERENCES plan(id),
  goal_id       TEXT NOT NULL,
  idx           INTEGER NOT NULL,            -- Day 序号 1..N
  title         TEXT NOT NULL,
  focus         TEXT,
  est_minutes   INTEGER NOT NULL DEFAULT 60,
  weight        REAL NOT NULL DEFAULT 1.0,
  status        TEXT NOT NULL DEFAULT 'locked',
  -- locked | learning | exam_ready | passed | partial | failed
  progress      REAL NOT NULL DEFAULT 0,      -- 0..1，由评分写入
  best_score    REAL NOT NULL DEFAULT 0,      -- 历史最高分 0..100
  material_refs TEXT,                         -- JSON 数组：["doc://xxx"]
  exam_focus    TEXT,                         -- JSON 数组，AI 出题方向
  started_at    TEXT,
  passed_at     TEXT
);
CREATE INDEX idx_day_plan ON day(plan_id, idx);

-- Day 内的任务勾选
CREATE TABLE task (
  id            TEXT PRIMARY KEY,
  day_id        TEXT NOT NULL REFERENCES day(id),
  idx           INTEGER NOT NULL,
  title         TEXT NOT NULL,
  est_minutes   INTEGER NOT NULL DEFAULT 0,
  acceptance    TEXT,                         -- JSON 数组：验收标准
  done          INTEGER NOT NULL DEFAULT 0,
  done_at       TEXT
);
CREATE INDEX idx_task_day ON task(day_id, idx);

-- 考试
CREATE TABLE exam (
  id            TEXT PRIMARY KEY,
  day_id        TEXT NOT NULL REFERENCES day(id),
  kind          TEXT NOT NULL DEFAULT 'day',  -- day | review
  status        TEXT NOT NULL DEFAULT 'created', -- created | submitted | graded | failed_ai
  model         TEXT,
  total_score   REAL,
  verdict       TEXT,                         -- pass | partial | fail
  feedback_md   TEXT,                         -- AI 总评
  started_at    TEXT NOT NULL,
  submitted_at  TEXT,
  duration_sec  INTEGER,
  prompt_tokens INTEGER DEFAULT 0,
  completion_tokens INTEGER DEFAULT 0,
  cost_cny      REAL DEFAULT 0
);
CREATE INDEX idx_exam_day ON exam(day_id, started_at);

-- 题目与作答
CREATE TABLE question (
  id            TEXT PRIMARY KEY,
  exam_id       TEXT NOT NULL REFERENCES exam(id),
  idx           INTEGER NOT NULL,
  type          TEXT NOT NULL,                -- choice | fill | short
  stem          TEXT NOT NULL,
  options       TEXT,                         -- JSON: ["A...","B..."]
  answer_key    TEXT,                         -- 仅供评分，UI 不展示
  user_answer   TEXT,
  score         REAL,
  max_score     REAL NOT NULL DEFAULT 100,
  rubric        TEXT,                         -- JSON: 各维度得分与证据
  comment       TEXT                          -- 逐题点评
);
CREATE INDEX idx_q_exam ON question(exam_id, idx);

-- 进度事件流水（可正可负，进度从这里重算）
CREATE TABLE progress_event (
  id            TEXT PRIMARY KEY,
  goal_id       TEXT NOT NULL,
  day_id        TEXT,
  delta         REAL NOT NULL,                -- 增量，如 +0.033 / -0.02
  reason        TEXT NOT NULL,                -- exam_pass | exam_partial | retest_fail | manual_adjust | replan
  ref_id        TEXT,                         -- exam_id 等
  note          TEXT,
  created_at    TEXT NOT NULL
);
CREATE INDEX idx_pe_goal ON progress_event(goal_id, created_at);

-- 材料文档
CREATE TABLE material (
  id            TEXT PRIMARY KEY,
  goal_id       TEXT NOT NULL,
  title         TEXT NOT NULL,
  content_md    TEXT NOT NULL,
  uri           TEXT,                         -- "doc://react-doc-jsx"
  source_path   TEXT,
  created_at    TEXT NOT NULL
);

-- 应用设置（不含密钥！密钥进系统钥匙串）
CREATE TABLE app_config (
  k TEXT PRIMARY KEY,
  v TEXT NOT NULL
);
```

### 状态机

```
day:   locked ──(前一个 Day passed)──→ learning
       learning ──(tasks 全部 done)──→ exam_ready
       exam_ready ──(交卷)──→ passed | partial | failed
       failed ──(重学)──→ learning
       partial ──(重考)──→ passed | partial
```

> 解锁规则：`day[1]` 初始为 `learning`；`day[i]` 是否解锁取决于 `day[i-1].status ∈ {passed, partial}`。
> 建议加一个「自由模式」开关，允许跳着学（但考试仍需按 Day 考）。

## 3. DeepSeek 集成

### 3.1 基本信息（2026-10 官方现状，务必以此为准）

- Base URL：`https://api.deepseek.com`（OpenAI 格式）/ `https://api.deepseek.com/anthropic`（Anthropic 格式）
- 认证：`Authorization: Bearer <API_KEY>`
- **`deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 下线**，当前只有两个模型：

| 模型 | 定位 | 上下文 | 最大输出 | 并发上限 |
|---|---|---|---|---|
| `deepseek-flash` | 便宜快，**出题/评分主力** | 1M | 384K | 2500 |
| `deepseek-v4-pro` | 更强，**生成计划、疑难评分** | 1M | 384K | 500 |

- **1M 上下文** → 整章教材可以直接塞进 prompt，**本项目不需要做 RAG**（这是重大简化）
- **思考模式默认开启**，通过 `extra_body: { thinking: { type: "enabled" | "disabled" } }` 切换，
  档位 `reasoning_effort: "none" | "low" | "high" | "max"`（默认 high）
- ⚠️ **思考模式下 `temperature` 完全无效**。要让温度参数生效，必须先 `thinking.disabled`
- 流式：`stream: true` + `stream_options: { include_usage: true }` 可拿到 token 用量

### 3.2 JSON 输出（两个坑）

```jsonc
// Chat Completions：只支持宽松 json_object
"response_format": { "type": "json_object" }
```

**坑 1：只支持 `json_object`，不支持 `json_schema` 严格模式。**
Prompt 中**必须出现 "json" 字样并给出格式示例**，否则可能返回空 content（官方明确提示"有概率返回空"，
甚至可能一直输出空白直到撞 `max_tokens`）→ 所以**必须自己做 Zod 校验 + 修复重试**，并设足 `max_tokens`。

**坑 2：想要严格结构化输出，得换 Responses API：**

```jsonc
// POST https://api.deepseek.com/responses
"text": {
  "format": { "type": "json_schema", "name": "study_plan", "schema": { /* JSON Schema */ } }
}
```

> **结论：**
> - **生成计划**（嵌套深、一次性、错一次返工大）→ 用 **Responses API + `json_schema`**，模型 `deepseek-v4-pro`
> - **出题 / 评分**（结构简单、高频）→ 用 **Chat Completions + `json_object`**，模型 `deepseek-flash`
> - 两条路径的返回值**仍然全部过 Zod**，不信任服务端

### 3.3 调用参数（本项目最终配置）

| 场景 | 模型 | API | 思考模式 | temperature | max_tokens | 超时 | 重试 |
|---|---|---|---|---|---|---|---|
| 生成计划 | `deepseek-v4-pro` | Responses + json_schema | enabled / high | 无效（忽略） | 32000 | 300s | 1 次 |
| 出题 | `deepseek-flash` | Chat + json_object | **disabled** | **0.9**（要多样性） | 4000 | 60s | 2 次 |
| 评分 | `deepseek-flash` | Chat + json_object | enabled（要判断力） | 无效 | 8000 | 120s | 2 次 |
| 双采样 | 同上 | 同上 | 同上 | — | — | — | 共 2 次取均值 |
| 补学建议 | `deepseek-flash` | Chat + json_object | disabled | 0.5 | 1000 | 60s | 1 次 |

**为什么评分开思考、出题关思考：**

- 评分需要"想清楚再给分"，思考模式质量明显更好；代价是 temperature 失效 → 用**双次采样取均值**来降抖动
- 出题需要多样性，必须让 `temperature` 生效 → 关思考模式
- 如果评分抖动仍然大（同一答案两次差 > 15 分），评分改用 `deepseek-v4-pro`（成本仍可忽略）

### 3.4 调用封装（伪代码）

```ts
async function callJSON<T>(opts: {
  model: string;
  messages: Message[];
  schema: ZodSchema<T>;
  thinking?: boolean;      // 默认 true
  temperature?: number;    // 仅 thinking=false 时生效
  maxTokens?: number;
}) {
  for (let attempt = 0; attempt < 3; attempt++) {
    const res = await fetch(`${BASE}/chat/completions`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${key}` },
      body: JSON.stringify({
        model: opts.model,
        messages: opts.messages,
        max_tokens: opts.maxTokens ?? 4000,
        response_format: { type: 'json_object' },
        thinking: { type: opts.thinking === false ? 'disabled' : 'enabled' },
        ...(opts.thinking === false && { temperature: opts.temperature ?? 0.5 }),
      }),
    });

    if (res.status === 429) { await sleep(2 ** attempt * 1000); continue; }
    if (!res.ok) throw new AIHttpError(res.status, await res.text());

    const data = await res.json();
    const text = data.choices?.[0]?.message?.content ?? '';
    const parsed = opts.schema.safeParse(tryParse(text));
    if (parsed.success) return { data: parsed.data, usage: data.usage };

    // 修复重试：把校验错误回灌给模型
    opts.messages.push(
      { role: 'assistant', content: text || '(空)' },
      { role: 'user', content: `上面输出不符合 schema，错误：${parsed.error.message}。请只返回合法 json。` },
    );
  }
  throw new AIOutputInvalidError();
}
```

**KVCache 省钱技巧：** 把**稳定的内容放在 prompt 最前面**（目标文档、教材原文），把变量放在最后。
缓存命中的输入只要 **0.02 元 / 百万 tokens**（未命中 1 元）。同一份材料反复出题、评分时成本可忽略。

### 3.5 错误与降级

| 情况 | 处理 |
|---|---|
| 401 / 余额不足 | 全局横幅提示，考试页禁用，保留本地手动作答入口 |
| 429 限流 | 指数退避（1s/2s/4s），提示"AI 排队中" |
| 超时 | 60s 后中断，可点「重试」 |
| JSON 校验连续 3 次失败 | 用**预置模板题**降级（从 material 自动生成填空题），评分进入 pending 队列 |
| 断网 | 题目与作答保存在本地，联网后补评分 |

> **原则：AI 挂掉时，学习流程不能断。** 允许先做题、后评分，进度条显示"待结算"。

## 4. AI 契约（三个 Prompt）

### 4.1 生成计划

**输入：** goal 文档 + 约束
**输出 Schema：**

```ts
const PlanSchema = z.object({
  title: z.string(),
  totalDays: z.number().int().min(1).max(365),
  stages: z.array(z.object({
    id: z.string(), title: z.string(),
    dayStart: z.number().int(), dayEnd: z.number().int(),
    weight: z.number().min(0).max(1),
  })),
  days: z.array(z.object({
    idx: z.number().int(),
    title: z.string(),
    focus: z.string(),
    estMinutes: z.number().int().min(20).max(180),
    tasks: z.array(z.object({
      title: z.string(),
      estMinutes: z.number().int(),
      acceptance: z.array(z.string()).min(1),
    })).min(1).max(4),
    examFocus: z.array(z.string()).min(1).max(5),
  })),
});
```

**Prompt 模板：**

```
你是一位学习规划专家。请根据用户的目标生成一份以「Day」为单位的可执行学习计划。

【硬性约束】
1. 每个 Day 的学习量严格等于 {minutesPerDay} 分钟（任务预计时长之和 = {minutesPerDay} ±10）。
2. 每个 Day 必须有 1-3 个任务，每个任务必须写出**可检验的验收标准**（"能说出……""能独立写出……"）。
3. 难度必须递进，后面 Day 可以依赖前面 Day 的产出。
4. 不要安排"复习日""休息日""机动日"这类空 Day。
5. 总 Day 数由目标难度反推，宁多勿少，但每个 Day 不能注水。
6. 只输出 json，不要任何解释文字。

【用户目标】
{goal_doc}

【已知材料】
{materials_or_none}

输出格式示例（务必严格遵守字段名）：
{"title":"...","totalDays":30,"stages":[{"id":"s1","title":"...","dayStart":1,"dayEnd":5,"weight":0.15}],
 "days":[{"idx":1,"title":"...","focus":"...","estMinutes":60,
          "tasks":[{"title":"...","estMinutes":25,"acceptance":["..."]}],
          "examFocus":["..."]}]}
```

**后处理校验（在本地做，不依赖 AI）：**

- `days.length === totalDays`，`idx` 连续从 1 开始
- 每个 Day 的 `estMinutes` 之和 ≈ `minutesPerDay`
- `stages` 的 `dayRange` 不重叠、覆盖全部 Day
- 任一项不满足 → 自动触发一次修复请求，再失败就展示给用户手动修

### 4.3 评分（整个系统最关键的调用）

**输入：** 题目 + 参考答案 + 用户答案
**输出 Schema：**

```ts
const GradeSchema = z.object({
  questions: z.array(z.object({
    idx: z.number().int(),
    score: z.number().min(0),
    maxScore: z.number(),
    dimensions: z.array(z.object({
      dim: z.enum(['准确性', '完整性', '迁移应用', '表达清晰']),
      weight: z.number(),
      score: z.number().min(0).max(1),   // 0~1 归一化
      evidence: z.string(),               // 必须引用用户原话
    })),
    comment: z.string(),                  // 50 字内点评
    isCorrect: z.boolean(),
  })),
  overallComment: z.string(),             // 100 字内总评
  weakPoints: z.array(z.string()),        // 薄弱点，用于生成补学任务
});
```

**Prompt 要点：**

```
你是严格的阅卷老师。请按评分标准给用户答案打分。

【铁律】
1. 只依据下面提供的参考答案要点与用户答案本身，不许引入外部知识。
2. 每一条 dimension 的 evidence 字段**必须引用用户答案中的原句**（用「」包起来），
   如果用户没写到，evidence 写「未提及」。
3. 宽松不等于正确：答案只沾边就只给部分分。宁可偏低，不许偏高。
4. 表达清晰只看是否易读，不影响知识准确性判断。
5. 只输出 json。

【评分标准】
准确性 40%：核心概念是否正确，有无事实性错误
完整性 30%：是否覆盖参考答案的要点
迁移应用 20%：能否举一反三/给例子/说明适用场景
表达清晰 10%：逻辑与可读性

【题目】
{question}

【参考答案要点】
{answerKey}

【用户答案】
{userAnswer}
```

**工程要求：**

- `temperature = 0.1`
- **双次采样**：跑两遍，取各维度均值；若两遍总分差 > 15 分 → 跑第三次取中位数
- 结果写入 `question.rubric`，UI 展示"AI 依据"（用户可申诉）
- 用户手动改分 → 写 `progress_event(reason='manual_adjust')`，不改原始评分记录

## 5. 进度算法（可执行版本）

```ts
// 一次考试结算
function settleExam(day: Day, graded: GradeResult) {
  // 1. 换算 0~100 总分
  const total = graded.questions.reduce((s, q) => s + q.score, 0);

  // 2. 映射 Day 完成度
  let progress = 0, verdict: Verdict;
  if (total >= 80)      { progress = 1.0;  verdict = 'pass'; }
  else if (total >= 60) { progress = 0.6;  verdict = 'partial'; }
  else                  { progress = 0.0;  verdict = 'fail'; }

  // 3. 只允许提升（重考取最高，不回退）
  const prev = day.progress;
  const next = Math.max(prev, progress);

  // 4. 写事件（增量 = 新进度 × 权重占比）
  if (next > prev) {
    recordProgressEvent({
      dayId: day.id,
      delta: (next - prev) * day.estMinutes,   // 分子增量
      reason: verdict === 'pass' ? 'exam_pass' : 'exam_partial',
      refId: graded.examId,
    });
  }
  updateDay(day.id, { progress: next, status: verdict, bestScore: Math.max(day.bestScore, total) });
}

// 总进度（渲染时计算，不缓存）
function goalProgress(goalId: string) {
  const days = getDays(goalId);
  const num = days.reduce((s, d) => s + d.progress * d.estMinutes, 0);
  const den = days.reduce((s, d) => s + d.estMinutes, 0);
  return den === 0 ? 0 : num / den;
}
```

**回退（复检失败）：**

```ts
function applyRetestFail(day: Day) {
  const prev = day.progress;
  const next = Math.max(0, prev - 0.2);
  recordProgressEvent({
    dayId: day.id, delta: (next - prev) * day.estMinutes,
    reason: 'retest_fail',
  });
  updateDay(day.id, { progress: next, status: next >= 1 ? 'passed' : 'partial' });
}
```

## 6. 成本估算

按"每天过 1 个 Day"计（单价以 `deepseek-flash` 空闲时段 1 元 / 4 元 计）：

| 调用 | 频率 | tokens | 单次成本 |
|---|---|---|---|
| 生成计划 | 每个目标 1 次（`v4-pro`） | in 2K / out 6K | ≈ ¥0.09 |
| 出题 | 每 Day 1 次 | in 2K / out 1K | ≈ ¥0.006 |
| 评分 | 每 Day ×2（双采样） | in 3K / out 2K | ≈ ¥0.011 |
| 补学建议 | 未通过时 | in 1K / out 0.3K | ≈ ¥0.002 |

**结论：每天约 ¥0.02（空闲）/ ¥0.04（高峰），一个月 1 元左右。**
即使全部改用 `deepseek-v4-pro` 评分，也不超过 **¥10/月**。
→ 所以**不要在评分上省钱**，优先保质量。

**两个省钱技巧：**

1. **错峰**：空闲时段（工作日 9:00-12:00 / 14:00-18:00 之外 + 周末 + 节假日）价格是高峰的一半
2. **KVCache**：把稳定内容（教材原文、目标文档）放 prompt 前缀，重复命中只收 0.02 元/百万 tokens

设置页仍要显示：**本月 tokens / 预估花费 / 各模型调用次数**，让成本透明。

## 7. 安全

- API Key 存 **Windows Credential Manager**（Rust 侧 `keyring`），前端永远拿不到明文
- 所有 AI 请求走 **Rust 后端**，前端只传业务数据
- 首次配置时明确告知："你的学习内容与答案会发送给 DeepSeek 用于出题和评分"
- 支持「离线模式」：不调用 AI，只做任务勾选 + 手动打分（数据不外发）
