## 0. 决策摘要（TL;DR）

| 项 | 决策 | 理由 |
|---|---|---|
| 桌面框架 | **Electron** | 本机无 cargo/rustc，Tauri 不可行；Electron 只需 Node |
| 前端 | **React 19 + TypeScript + Vite** | 生态最稳，子代理并行开发不易冲突 |
| 构建 | **electron-vite** | 一套配置同时管 main/preload/renderer，热更新可用 |
| 数据库 | **sql.js（SQLite WASM）+ JSON 落盘** | 零原生编译（本机无 MSVC 构建链），保留完整 SQL |
| 状态管理 | **Zustand** | 轻、无样板代码 |
| 图表 | **自绘 SVG** | 不引第三方图表库，体积小、样式统一 |
| 校验 | **zod** | AI 输出与 IPC 入参统一校验 |
| AI | **DeepSeek 全量 `deepseek-flash`（V4.1-Flash-1017）** | 用户指定；1M 上下文，无需 RAG |
| 密钥 | **Electron safeStorage（DPAPI）+ 仅主进程持有** | 渲染进程永远拿不到 Key |

**一屏架构**：

```
┌──────────────────────── Electron ────────────────────────┐
│  Renderer (React)          │  Main (Node)                 │
│  pages / components        │   ipc handlers               │
│  zustand store             │    ├─ db (sql.js → app.db)   │
│         │                  │    ├─ ai (DeepSeek client)   │
│         │ contextBridge    │    └─ fs (materials/reports) │
│         ▼  白名单 IPC      │  safeStorage ← API Key       │
└──────────────────────────────────────────────────────────┘
```

渲染进程 `nodeIntegration: false`、`contextIsolation: true`，只能调 `window.api.*`（白名单，见 contracts）。

## 2. 数据流与关键规则落点

### 2.1 主流程

```
创建目标 → AI 生成计划(Days+Tasks) → 确认保存
   → 今日学习：勾选 Task → 全部完成 ⇒ day.status = exam_ready
   → 考试：2 道客观题 + 1 段费曼复述 → AI 评分
        ≥80 passed（progress = 1）· 60–79 partial（progress = 0.6，可重考）· <60 failed
   → 写 progress_event → 看板进度条增长
```

### 2.2 进度（唯一真相源 = progress_event 流水）

- `goal.progress = Σ(day.progress × day.estMinutes) / Σ(all day.estMinutes)`，实时算，不落冗余字段。
- 写入只追加事件：`{goalId, dayId, delta, reason, detail}`。
- 复检答错 → 追加负 delta（-0.2 × 该 day 权重）。
- **禁止**任何地方直接 `UPDATE progress = x`。

### 2.3 Day 状态机

`locked → learning → exam_ready → passed | partial | failed`
- `learning → exam_ready`：该 day 全部 task.done
- `failed → learning`（可重做 task）、`partial → exam_ready`（可重考）

### 2.4 考试计分（含费曼，替代 02 文档的旧口径）

| 组成 | 分值 | 评分方 |
|---|---|---|
| 客观题 ×2（单选/填空） | 25 × 2 = 50 | **主进程规则判分，不花 token** |
| 费曼复述 | 50 | AI（分维度打分） |
| 合计 | 100 | ≥80 通过 / 60–79 部分 / <60 未通过 |

费曼复述 50 分拆解：**概念准确性 18 / 覆盖完整性 12 / 举例恰当性 10 / 讲解清晰度 6**。
客观题答对即得分，无部分分；填空允许 3 种等价写法由 AI 生成的 `answerAliases` 覆盖。

## 3. 费曼复述模块（新增功能，重点）

### 3.1 为什么放在考试里

费曼法的价值是「讲不清 = 没学会」。把它做成考试的最后一道题，既有仪式感，又能逼用户真的把 Day 内容组织出来；同时复用同一个评分与解锁流程，不做独立入口，减少界面复杂度。

### 3.2 交互（3 步，共 5–8 分钟）

```
① 题面：AI 给出「你要教会一个零基础新人」的场景 + 本 Day 的 2–3 个必须讲到点（隐藏，不展示给用户）
② 用户用大白话讲解（文字输入，≥120 字才能提交）
③ AI 扮演学生，只追问 1 个问题（针对讲解里含糊/错误/跳步的地方，严禁反问式给答案）
④ 用户补充回答（≥40 字）
⑤ 提交 → AI 按 4 维度打分 + 指出 1 个最大漏洞
```

### 3.3 状态机

`awaiting_explain → (user 文本) → awaiting_followup_answer → (user 文本) → grading → graded`

数据库表 `recitation`：

```sql
CREATE TABLE IF NOT EXISTS recitation (
  id              TEXT PRIMARY KEY,
  exam_id         TEXT NOT NULL REFERENCES exam(id) ON DELETE CASCADE,
  status          TEXT NOT NULL DEFAULT 'awaiting_explain',
  prompt          TEXT NOT NULL,              -- 题面（AI 生成的学生场景）
  key_points      TEXT NOT NULL,              -- JSON: 必须覆盖的要点（隐藏）
  messages        TEXT NOT NULL DEFAULT '[]', -- JSON: [{role:'user'|'student',text,at}]
  follow_up       TEXT,                       -- AI 的追问
  score           INTEGER,                    -- 0–50
  dimensions      TEXT NOT NULL DEFAULT '{}', -- JSON: {accuracy,coverage,example,clarity}
  feedback        TEXT,                       -- AI 点评（≤120 字）
  critical_gap    TEXT,                       -- 最大漏洞
  model           TEXT,
  created_at      TEXT NOT NULL,
  graded_at       TEXT
);
```

### 3.4 追问 Prompt 要点（写进 `prompts.ts`）

- 人设：一个**真的没学过该知识**、爱较真的学生，语气自然，1–2 句。
- 只能问 **1 个**问题，且必须引用用户原话里的具体片段。
- **禁止**：给出答案、给出提示、反问"是不是……"、一次问多个点。
- 如果用户讲解基本正确 → 追问一个「迁移应用」问题（换个场景还成立吗）。
- 输出纯文本，≤80 字。

### 3.5 评分 Prompt 要点

- 输入：题面、隐藏要点、用户两轮回答、追问。
- 输出严格 JSON：`{dimensions:{accuracy,coverage,example,clarity}, score, feedback, critical_gap}`。
- `score` = 各维度按权重折算后求和，模型只给**各维度 0–1 的达成度**，分数由主进程折算（避免模型算术飘）。
- 判分尺度（写死在 Prompt 里，保证跨 Day 可比）：
  - 准确性 1.0 = 无错误且有正确因果关系；0.6 = 方向对但有 1 处含混；0.2 = 关键概念说错
  - 完整性 1.0 = 覆盖全部隐藏要点；按覆盖比例递减
  - 举例 1.0 = 有贴切自造例子；0.5 = 沿用材料里的例子；0 = 无例子
  - 清晰性 1.0 = 无术语堆砌、有结构（先结论后解释）；0.5 = 能懂但绕；0 = 看不懂

## 4. AI 接入规范

### 4.1 模型与调用方式

统一 `model: "deepseek-flash"`（= DeepSeek-V4.1-Flash-1017）。按场景选通道：

| 场景 | 通道 | thinking | 结构化 | 超时 |
|---|---|---|---|---|
| 生成计划 | Responses API `/responses` | **none**（结构化输出不吃思考） | `text.format` json_schema | 180s |
| 出题 | Responses API | **none** | json_schema | 120s |
| 费曼追问 | Chat Completions `/chat/completions` | **disabled**（要快） | 纯文本 | 45s |
| 费曼/简答评分 | Responses API | **none** | json_schema | 120s |
| 复检出题 | 本地复用旧题 | — | — | — |

> **为什么不同通道**：Chat Completions 的 `response_format` 只支持 `json_object`，官方明确「可能返回空 content」；需要严格字段结构时走 Responses API 的 `json_schema`，最稳。
>
> **为什么关思考**：`deepseek-flash` 思考默认开启，reasoning token 与正文共用 `max_output_tokens`；实测 8k 预算下思考吃掉 7.9k、正文为空（`status=incomplete`），仍照常计费。

### 4.2 client.ts 必做

1. 指数退避重试 3 次，429/5xx 才重试，读 `Retry-After`；超时不重试。
2. 统一超时（AbortController）。
3. 每次调用写 `ai_usage`（model、scene、prompt_tokens、completion_tokens、cache_hit_tokens、cost、latency、ok）。
4. 错误翻译成中文可读文案（`401 → API Key 无效`、`402 → 余额不足`、`429 → 请求过快`）。
5. **思考模式注意**：不要传 `temperature`（无效）；`top_p` 只在思考模式生效。
6. 记录 `reasoning_content` 到日志（不展示给用户）。

### 4.3 成本控制

- 稳定材料（目标描述、教材章节）固定放在 prompt 前缀 → 吃 KVCache（0.02 元/M）。
- 客观题本地判分，不调 AI。
- 预估：一个目标 30 天，月成本 ≈ ¥1–3。

## 附录：落地实现记录（2026-10-20）

MVP 已跑通并实机验收（真实 Electron 窗口 + sql.js 落盘，无 AI Key 的全链路 38 项冒烟断言全绿）。落地时踩到、且文档层面值得留档的问题：

| 问题 | 现象 | 处理 |
|---|---|---|
| preload 入口 | `electron-vite build` 报 `An entry point is required in the electron vite preload config` | electron-vite 默认找 `src/preload/index.ts`，本项目 preload 在 `src/main/preload.ts`，需在 config 的 preload 段显式 `build.rollupOptions.input` |
| Electron 二进制 | `npm i` 后 `node_modules/electron/dist` 缺失，`@electron/get` 走 npmmirror 下载卡死 | 手工从 `https://cdn.npmmirror.com/binaries/electron/44.9.0/electron-v44.9.0-win32-x64.zip` 下载解压到 `dist/`，并写 `path.txt` |
| `ELECTRON_RUN_AS_NODE` | 某些 shell 环境注入了该变量，启动后报 `Cannot read properties of undefined (reading 'isPackaged')` | 启动前 `Remove-Item Env:ELECTRON_RUN_AS_NODE`；冒烟脚本里也主动剔除 |
| sql.js 外键级联 | `PRAGMA foreign_keys = ON` 后 `DELETE FROM goal` 未触发表联级联，留下 plan/day/task 孤儿行，统计时长虚高 | 两道保险：`deleteGoal/deletePlan` 在事务里显式逐表删除；`database.ts` 启动时 `pruneOrphans()` 多轮 `NOT IN (SELECT id FROM 父表)` 自愈，冒烟断言「清场后 totalMinutes === 0」 |
| 资料导入（同日追加） | 后端早有 `material:add`，但渲染层完全没有资料入口，用户无法把教材文件喂给 AI | 新增 `src/main/util/importer.ts`（.md/.markdown/.txt/.docx → 纯文本，单份 8MB、单次 20 份、单份 20 万字上限），`material:import` 弹系统文件框、单份失败只进 `skipped` 不中断；计划页新增「学习资料」卡片（列表 / 移除 / 继续导入） |
| 冒烟污染真实库 | 冒烟直接读写 `%APPDATA%/StudyFlow`，测试目标、AI 成本会留在用户库里 | `scripts/smoke.mjs` 传 `SF_USER_DATA=.tmp-smoke-data`，`src/main/index.ts` 在 app ready 前 `app.setPath('userData', …)`，每次跑都是全新库；配套 `scripts/fixtures.mjs` 生成 .md/.docx/.pdf 素材 |
| Responses 预算被思考吃光 | 计划生成报 `AI 没有返回结构化内容`；`ai_usage` 显示 `completion_tokens=7997/8003`（打满 8k）、`status=incomplete`，仍计费 | 结构化调用统一传 `reasoning: { effort: 'none' }`；`incomplete_details.reason=max_output_tokens` 时预算翻倍重试一次并给可读文案；计划预算提到 16k |
| strict json_schema 不支持联合类型 | 出题报 400 `Invalid json schema: field type: unknown variant array` | `options` 从 `type: ['array','null']` 改为单值 `type: 'array'`（填空题给空数组），`normalizeExam` 再区分题型；新增 `scripts/schema-lint.mjs` 静态拦截联合类型并接入 `npm run smoke` |
