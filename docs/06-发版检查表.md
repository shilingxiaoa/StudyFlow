## 3. 发布

| # | 检查项 | 做法 | 通过标准 |
|---|---|---|---|
| 3.1 | 提交与 tag | `git tag -a v<ver> -m "..."` → `git push origin main --tags` | 远端 tag 与提交一致 |
| 3.2 | 等 CI 产出 Release | 推 tag 后看 Actions 的 **Release** 工作流（Windows runner，约 4–6 分钟） | 工作流绿 |
| 3.3 | **核对 Release 附件**（必做） | 打开 `releases/tag/v<ver>`，确认有 `StudyFlow-<ver>-setup.exe`、`StudyFlow-<ver>-portable.exe`、`latest.yml`、`.blockmap` 四件 | 四个附件都在且非 draft |
| 3.4 | 附件缺失时手动补传 | 见下方「补传命令」 | 补完刷新页面可见 |
| 3.5 | 更新链路自检 | 装旧版启动 → 设置页「检查更新」 | 提示「发现新版本 v<ver>」 |
| 3.6 | 回滚预案 | 记录上一版 tag 与下载地址 | 出问题能退回 |

**补传命令**（CI 偶尔只传上 `.blockmap`，实测 1.8.1 出现过；以 `--data-binary` 传，别用 PowerShell 反引号续行——会把命令拆坏）：

```powershell
$tok = (@("protocol=https","host=github.com","") | git.exe credential fill | Where-Object { $_ -like 'password=*' }) -replace '^password=',''
$id  = (curl.exe -s -H "Authorization: Bearer $tok" "https://api.github.com/repos/shilingxiaoa/StudyFlow/releases/tags/v1.8.1" | ConvertFrom-Json).id
$up  = "https://uploads.github.com/repos/shilingxiaoa/StudyFlow/releases/$id/assets"
curl.exe -sS -X POST -H "Authorization: Bearer $tok" -H "Content-Type: application/octet-stream" --data-binary "@release/StudyFlow-1.8.1-setup.exe" "$up`?name=StudyFlow-1.8.1-setup.exe"
```

> 注意：`electron-builder` 默认把 Release 建成 **draft**，草稿自动更新读不到；`package.json` 里必须带 `"releaseType": "release"`（v1.8.1 已修）。
