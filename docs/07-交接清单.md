> 目的：任何 agent（或你换一台电脑）接手时，**不用问人**也能在 10 分钟内进入可交付状态。

## 1. 交接前你必须知道的 5 件事

1. 这是**单机优先**的桌面应用，没有线上服务；所有数据在 `%APPDATA%\StudyFlow\`。
2. 唯一可信验收是 `npm run smoke`（真实 Electron、82 项、直调 IPC）。**不要**用「类型检查过了」当完成。
3. `src/shared/contracts.ts` 是唯一契约；谁改它，谁负责同步主进程和渲染层。
4. 本机是 Windows + PowerShell，有一批环境坑（见 `AGENTS.md` §5），每条都真实踩过。
5. 版本号只改 `package.json`；发版走 `docs/06-发版检查表.md`。

## 2. 交接三步（10 分钟）

### 第一步：确认仓库状态干净

```powershell
git status --short          # 必须为空
git log --oneline -3        # 应为 9379607（或之后的提交）
node -p "require('./package.json').version"   # 1.8.1
```

### 第二步：跑一次验收（确认环境可用）

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
npm install                 # 首次/换机
npm run verify              # 双 tsc + schema-lint
npm run smoke               # 期望：通过 82 / 失败 0
```

### 第三步：把「当前任务」交给它

在 Codex 里第一条消息直接贴下面模板（把 `<任务>` 换掉）：

```

3) 改完必须跑 verify + smoke，并贴出结果。
```

## 6. 并行规则（我 + Codex 同时干活时）

- **单写者文件**：`src/shared/contracts.ts`、`src/main/db/schema.sql`、`package.json`、`electron.vite.config.ts`。谁要改先在聊天里说，改完立刻 `git commit`，另一方 `git pull` 再继续。
- **不要并行 build**：`npm run build` / `npm run dist` 会抢 `out/`、`release/`。串行跑。
- **页面按文件划分**：一人一页（`pages/X.tsx` + `pages/X.css`），不要两个 agent 改同一页。
- **提交粒度**：一次一个可验证的改动；提交信息写「为什么」，不只写「改了什么」。

## 7. 回滚方式

```powershell
git log --oneline            # 找到上一个好提交
git restore <file>           # 撤销未提交改动
git reset --soft HEAD~1      # 撤销最近一次提交（保留改动）
git revert <sha>             # 已推送的提交用 revert，别 force push
```

数据回滚：`%APPDATA%\StudyFlow\` 下每个账号一个 `users/<id>/studyflow.db`，改动 schema 前先复制一份备份。

## 8. 为什么要写这些（决策记录）

| 决策 | 原因 |
|---|---|
| 本地多账号而不是云账号 | 用户要「先跑通登录」，云端要数据库+备案，成本与周期都重 |
| 契约集中在 `contracts.ts` | 主进程/渲染层通过 IPC 通信，类型必须单一真源，否则两边漂移 |
| 冒烟直调 IPC 而不是点 UI | UI 断言脆弱；业务链路用 IPC 能稳定覆盖 82 项 |
| 计划骨架 + 按天教案 | 一次生成整份教案太贵；按天按需生成，¥0.013/天 |
| 计分从 3 题改 7 题、取消填空 | 用户要更多选择题、取消填空题、取消「举例」维度 |
| 取消 Day 解锁 | 用户明确「不要按顺序做」 |
| GitHub Releases 做更新源 | 零成本、已有 CI；R2/OSS 要额外配置 |
